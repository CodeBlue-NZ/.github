## 🚀 Internal Developer Onboarding

If you are a new CodeBlue engineer, contractor, or technical team member, please complete your local workplace setup using the steps below [.1.1]:

* **Engineering Handbook:** Review our development standards, architecture rules, and deployment policies on our secure company intranet.
* **Workplace Tooling:** Ensure your machine is provisioned with our standard Microsoft Modern Workplace and Copilot developer extensions [.1.1].
* **Access Control:** To request permissions for specific private microservices, cloud sandboxes, or database environments, log an IT Procurement & Access ticket [.1.1].

## 📂 Core Architecture & Internal Domains

*💡 **Tip for CodeBlue Teams:** Keep our primary active codebases pinned to the top of the organization dashboard for faster day-to-day navigation.*

## 🤝 External Collaborators & Customers

Welcome to the CodeBlue ecosystem. If you are an external vendor, contractor, or customer partner granted access to specific repositories in this organization [.1.1]:

* **Scope of Access:** Your authorization is strictly sandboxed to the explicit private repositories assigned to your joint project or service engagement.
* **Security Compliance:** All code commits must comply with CodeBlue's strict risk-management frameworks [.1.1]. Never commit credentials, environment secrets, or customer PII.
* **Communication Rules:** Please handle all project technical discussions using the **GitHub Issues** or **Discussions** tabs within your assigned repository rather than using CodeBlue's internal communication loops.
* **Governance:** All actions taken within this organization remain strictly subject to active Master Services Agreements (MSAs) and Non-Disclosure Agreements (NDAs) [.1.1].

## 🛡️ Security Policy & Emergency Support

* **Spotted a Security Risk?** Do not create an issue log. Report potential vulnerabilities immediately via the CodeBlue Security Incident channel or email `security@codeblue.co.nz` [.1.1].
* **Infrastructure Emergencies:** For critical service delivery, backup failures, or down networks, contact the on-duty vCIO or internal infrastructure response team [.1.1].
* **IT Service Desk:** For GitHub multi-factor authentication (MFA) resets or repository provisioning, contact internal IT support [.1.1].
